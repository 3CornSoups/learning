# MiniMax H3：少步蒸馏、二阶段采样与产线权重

> 以本项目收录的源码片段、配置快照和 2026-11-10 权重融合记录为主。区分本地有实现/配置、论文或外部项目报告、以及已证实生产正在运行。归档记录可以说明方案与配方，不能单独证明当前线上服务健康或仍在使用。

## 1. 一页结论

- H3 后训练不止 RL。偏好优化可用 SFT、Flow-GRPO、DiffusionNFT；减少推理 NFE 的是 DMD 家族、SGMD、Consistency/轨迹蒸馏等。后者训练少步生成器，不应统称 RL。
- 本地可核对的 H3 少步训练实现包括 DMD 4-NFE LoRA、SGMD 4-NFE LoRA；另有 dCM→DMD→可选 rCM 实验代码与配置。minimax-h3-rcm 归档没有训练产物/权重，不能写成已成功产出。
- 二采是推理流程：低分辨率先确定结构，再把 latent 放大、重加噪，在高分辨率继续采样。它可能比相同 NFE 全程高分辨率更快；跟 4-step 高清直出相比，因多跑一段和 upscaler，通常会更慢。画质与漂移由切换噪声、高清 NFE、放大器共同决定。
- SeedVR/SeedVR2 是独立视频恢复/增强模型，不是 H3 蒸馏器，也不减少 H3 NFE。它们可以补纹理，也可能改写/幻觉局部细节；“单步”指恢复网络的推理步数，不能理解成免费后处理。
- 最新可审计 Agnes 配方记录日期为 2026-11-10，含 FL2VA 与 REF2VA 两套。SGLang 端到端日志在 qwen3_asr 配置注册处导入失败；因此本文称它为“最新归档配方”，不说成在线验证成功的当前权重。

## 2. H3 后训练方法地图

| 目标 | 方法例子 | 训练结果 | 本地证据/状态 |
|---|---|---|---|
| 更符合任务/偏好 | SFT、Flow-GRPO、DiffusionNFT | 任务 LoRA 或权重 | RL 训练材料、配置和实验说明；不是少步蒸馏 |
| 减少生成步数 | DMD、SGMD、dCM/rCM、PDMD、DMAD、PTD、VA-TDM | 少步 student，常以 LoRA 发布 | DMD/SGMD 有本地 H3 源码；rCM 有研究配置；其余按论文/公开仓库，非本目录权重 |
| 生成中提高空间细节 | latent 二采、分辨率切换 | 不一定改基模；可能有 learned 3D latent upscaler | SGLang 两阶段包、CLI/API 参数和映射实现 |
| 成片后恢复 | SeedVR、SeedVR2、SwiftVR-family | 独立增强模型 | 后处理；本地 SwiftVR 不应直接等同官方 SeedVR2 权重 |
| 每步少算 | Flash/Sage/Sparse Attention、cache | 算子/缓存配置 | 与蒸馏、二采正交，但收益不简单相乘 |

## 3. DMD：一轮训练究竟怎样发生

### 3.1 训练对象

本地 H3 DMD 使用三个逻辑角色：冻结的真实分布 teacher、可训练的生成 student、可训练的 fake-score 网络（代码以 Fake LoRA 适配器承载）。推理时仅需 student adapter；teacher 与 fake-score 只在训练期参与。配置目标为 4 NFE，student 以 LoRA 形式更新。

### 3.2 Student 更新

1. 取 prompt 和随机噪声，student 用 4 个离散时间点 rollout，得到生成 latent G。训练时随机抽取终止节点，梯度只从最后一步回传。
2. 从生成结果与高斯噪声混合出带噪样本：x_t = (1−σ)G + σε。
3. teacher 和 fake-score 分别预测。H3 这段实现按 velocity 符号约定还原数据预测：x0 = x_t + σv。
4. 两个 x0 的差构成分布校正方向，并按 teacher 残差尺度归一化：g ≈ (x0_fake − x0_teacher) / mean(|G − x0_teacher|)。
5. 用 stop-gradient 伪目标更新 student：L_student = 1/2 · ||G − stopgrad(G − g)||²。这等价于把 g 作为梯度方向传给生成结果，不是直接拟合 teacher 的固定轨迹。
6. 同批数据更新 Fake：它拟合 student 生成结果的噪声/速度目标，代码目标可写成 G − ε。本地 student:Fake 更新比为 1:5。

音视频 H3 训练会保持模态对应并组合相应损失；需要关注打包序列拆分、速度符号和 data-fraction 时间定义。照搬 SD 整数 timestep 或 velocity 符号可能把去噪方向弄反。

### 3.3 本地代码位置

- Trainer 与 DMD loss：[DMD trainer](code/dmd/minimax_h3_trainer.py)、同目录 [math.py](code/dmd/math.py)
- 配置：[DMD YAML](code/dmd/minimax_h3_t2av_dmd_lora.yaml)；4 NFE、768×1344×243、video/audio loss 各 1.0、Fake 更新比 5。训练用 prompt_cache，不读取成对真实视频。
- 重点看 terminal-step 随机采样、伪目标 stop-gradient、Fake 更新循环、音视频 loss 组装。

这是本地 H3 DMD trainer，不应直接称为完整 DMD2 复现。DMD2 原论文另加入 GAN/判别器目标和训练稳定技巧；除非核对具体分支实现，不要把 DMD2 全部特征归因给 H3 trainer。

## 4. 几种 DMD 家族方案怎么区分

| 方法 | 核心监督 | student / fake 更新特点 | 本地 H3 状态 |
|---|---|---|---|
| DMD | Teacher score 与 Fake score 的差给 student 分布匹配方向 | 同时训练 student 与 fake-score；交替更新 | 有 H3 4-NFE LoRA trainer；student:Fake=1:5 |
| DMD2 | DMD 分布匹配加对抗判别目标等稳定技巧 | 判别器/损失组合依论文和实现而异；不等同“DMD 自动等于 DMD2” | 当前 trainer 不能据此标注完整 DMD2 |
| SGMD | Teacher-stop-gradient Fisher + negative-residual（NR）更新生成器；residual-contraction（RC）更新 fake score | 本地实现 1:1；student 步经 fake prediction 回传 latent，fake 参数该步冻结；phase2 λ=.05 | 有 H3 trainer/config；phase2 4 NFE、704×1280、209 帧、correction weight .05 |
| dCM→DMD→rCM | 先 consistency matching，再 DMD，可选 rectified consistency matching | 多阶段目标，各阶段作用不同 | 有实验代码/config；无已归档 checkpoint |
| PDMD | progressive DMD 路线 | 公开 H3 2/4-step 结果；按阶段减少步数 | 依公开论文/官方项目，不是本地上述 trainer 的别名 |
| DMAD | 对抗式分布匹配构造 few-step 蒸馏 | 论文报告 H3 4-step | 依公开论文/项目；区别于本地 Fake-score DMD |
| PTD / VA-TDM | 轨迹监督、多视角 teacher 蒸馏等 | 具体目标与附加模块见论文 | 文献/公开实现状态；不能说本地已有对应线上权重 |

### SGMD：student 和 fake-score 各更新一次

本地 SGMD trainer 对每次迭代的更新顺序是：

1. Student 按随机终止点做 4-NFE rollout，得到视频与音频 latent；用同一组 sigma/noise 构造 noisy input。
2. Teacher 与 Fake-score 预测 x0。Student 的生成器目标为 teacher-stop-gradient Fisher loss + λ·NR（negative residual）；Fake 参数在这一步不更新，但 fake prediction 保留对输入 latent 的梯度，因此梯度可以穿过 fake 回到 student。
3. 用刚生成的 latent 更新 Fake-score：优化 λ·RC（residual contraction），把 student 生成 latent stop-gradient。代码还计算 velocity MSE 作为诊断值，但实际返回给 fake optimizer 的目标是 RC。
4. 每轮严格按 student 1 次、fake 1 次更新；phase2 YAML 的 λ 为 0.05。和 DMD 的 Fake 1:5 更新比不同，不能把论文里的跨模型训练加速倍数当成本地 H3 的 wall-clock 测量。

**步数不能脱离配置谈。** NFE 是 student 一次生成实际调用 DiT 的次数；训练 rollout 次数、Fake/teacher 的额外前向不算部署 NFE。4-NFE LoRA 要按配套 scheduler 和 adapter 使用，不能随意改成 1 步或任意换 scheduler 后仍期待同质量。

### 本地 SGMD 配置细节

[SGMD trainer](code/sgmd/minimax_h3_sgmd_trainer.py) 是 H3 SGMD trainer。[SGMD phase2 YAML](code/sgmd/minimax_h3_t2av_sgmd_lora_formal_phase2.yaml) 指向 4 NFE、fake update ratio 1、704×1280、209 帧、correction weight 0.05。早期配置使用过 .1 和不同画布，数字必须与具体 config 对齐。论文中 Wan 的约 3× 速度不是本地 H3 端到端基准。 原始归档保留了 SGMD 配置与 W&B 运行记录；公开快照不含这些日志，且归档没有可直接部署的 student checkpoint。

### rCM 实验分支

归档中的 minimax-h3-rcm 含 dcm_8gpu.yaml、dmd_8gpu.yaml、rcm_8gpu.yaml；这些配置未复制到公开快照，包括 4 NFE、fake ratio 5、lambda_dmd=.01 等配置。归档没有 checkpoint 和可复核训练产出，因此不称为已训成的产线 LoRA，也不泛化成论文里的所有 sCM/JVP 变体。

## 5. 偏好/RL 后训练：两条路线，和少步蒸馏目标不同

这两类方法让采样结果更符合奖励/偏好，优化的是策略输出分布；它们本身不保证把 20–50 NFE 压成 4 NFE。少步生成要用后面的 DMD/SGMD 等蒸馏路线。

| 路线 | 原理与奖励 | H3 配方记录 | 适用边界 |
|---|---|---|---|
| Flow-GRPO | 把确定性 ODE 采样改写为可计算 log-prob 的 SDE；对同一 prompt 采一组结果，按组内相对奖励更新 LoRA，并只对部分去噪步回传以控制成本 | miles_diffusion / PR #154 方案；2 卡；只训练视频分支、冻结音频；PickScore 单奖励。归档实验表记录 eval PickScore 0.806→0.816 | 适合先做视频偏好优化；奖励不直接衡量音频与视频同步 |
| DiffusionNFT | 不要求采样器提供 log-prob；对输出做前向加噪构造正负样本对，再按奖励信号做 NFT 更新 | verl-omni 全模态方案；8 卡；联合 T2VA/FL2VA；LoRA r=64、alpha=128；CLAP（音频-文本）+ ImageBind（音频-视频）；训练 256×384，验证 512×768、121 帧。归档记录 reward 0.41→0.51 | 可接黑盒采样器并联合音视频优化；奖励模型覆盖不到的属性不会自动改善 |

上述 GPU 数、画布和曲线是本地学习材料中归档的实验/配方记录，不是跨硬件 benchmark。当前 verl-omni 归档包含全模态训练框架与 DiffusionNFT 组件；Flow-GRPO 方案引用 miles_diffusion PR #154。阅读其结果时应视为项目记录，不等同于当前线上模型。SFT 则是用 prompt 与目标视频/音频配对数据做监督拟合，适合明确的风格、任务或条件适配；它需要成对样本，不能替代偏好奖励，也不会自动获得少步采样能力。

## 6. 二阶段采样：路线、速度和质量

二采在生成过程中做尺度切换，常见路径是低清 H3 先出结构与运动 → learned 3D latent upscaler 放大 → xσ=(1−σ)x0+σε 重加噪 → 高分辨率 H3 继续去噪 → VAE 解码。噪声 σ 越大，越接近重新生成，细节改动更多，语义/构图漂移风险也越高。

| 路线 | 怎么做 | 速度直觉 | 画质与风险 |
|---|---|---|---|
| Full-X0 latent | 第一段完整到 x0，latent 放大重加噪，再跑高清 NFE | 比相同总步数全程高清便宜；多了 upscaler 和高清阶段 | 结构通常较稳；高清阶段可以重绘纹理 |
| Mid-trajectory | 在中途切换，用预测 x0/当前轨迹放大并接下一 σ | 少跑低清尾段；取决于切点和桥接逻辑 | 切点预测误差会放大，衔接不好易闪/漂 |
| 直接低清 latent 插值 | 插值或上采样 latent 后继续采样 | 省掉 learned upscaler，但不是等价超分 | 可能平滑、丢时序/高频信息 |
| 像素域 i2i | 解码低清视频、像素超分、重新编码，再高分辨率采样 | VAE 往返和放大器增加时间 | 编解码损失、重加噪导致外观变化 |
| 局部裁剪精修 | 只选脸/手等区域增强 | 全局 token 少；需裁剪、拼接和时序跟踪 | 接缝、身份漂移、跨帧不稳 |
| 成片后恢复 | 生成完成后接 SeedVR/SeedVR2 类模型 | 纯增加一段模型耗时 | 可补纹理，也可能幻觉内容；不减少 H3 NFE |

粗略成本为 T≈N1·c_low+T_up+N2·c_high+T_decode。若宽、高各减半，空间 token 约为 1/4；全注意力的二次项单步注意力理论上约 1/16。实际端到端还受 DiT 其它算子、VAE、upscaler、显存和调度影响，不能把理论比率当实测加速。

本地 SGLang 包里 CLI 默认对非 480P 使用 8+5、480P 默认旁路；映射/API 路径的 AGNES_TWO_STAGE_SPLIT_STEP 默认是 4，并允许环境变量覆盖。 更完整的路线分类、参数入口与验收建议见 [二阶段采样专题](docs/二阶段采样技术科普.md)。**不是统一线上默认**。8+5 相对同 13 步全高清通常会快；相较 4-step 高清直出则多了 9 个 NFE 和 upscaler，通常更慢。高清精修 NFE/噪声越高，细节可塑性与算力、漂移风险也随之上升。归档 SGLang e2e 日志导入 qwen3_asr 配置时失败，只能确认实现和参数存在，不能证明线上成功运行。

### SeedVR 和 SeedVR2

SeedVR（CVPR 2025）是视频恢复框架，关注长视频/任意分辨率的高效视频恢复；SeedVR2（ICLR 2026）是后续独立方法，使用一步扩散与对抗式后训练、特征匹配和自适应窗口注意力。它们作用于低质/低清视频增强链路，不是 H3 teacher/student 蒸馏算法。一步生成仍需完整运行一个大恢复网络，所以会增加总延迟；它负责补纹理，不能保证逐局部忠实。仓库 SwiftVR 集成称为 SeedVR2-family，不据此断言加载了官方 SeedVR2 checkpoint。

## 7. 最新可审计权重组合：Agnes 2026-11-10 记录

记录文件：[Agnes 权重融合与 SGLang 产线记录](docs/Agnes权重融合与SGLang产线记录.md)。它保存 merge manifest/配方，档案未包含完整融合权重。两条路径如下：

| 产物 | Base | LoRA / scale | 导出记录 |
|---|---|---|---|
| Agnes-2.6-1016-FL2VA-FP8 | MiniMax-H3 FL2VA | OpenVDN stage-dmd-step-250/adapters/turbo/adapter_model.safetensors，mode=back_0.7；Combat V2 global_scale=.6；Realism People global_scale=.3 | FP8 E4M3 |
| Agnes-2.6-1018-REF2VA-FP8 | 官方 MiniMax-H3 REF2VA BF16 | Larryvrh Turbo V4 Step600 EMA flat 1.0；Combat V2 .6；Realism People .3 | manifest 标 1018-v5-turbo-flat1.0；FP8 E4M3 |

REF2VA manifest 还给 Combat/Realism 配了层级 scale：Token Refiner 1.0；blocks 0–4 为 .7，5–24 为 1.0，25–29 为 .6，30–34 为 .4，35–39 为 .1，40–49 为 0。Global scale 与分层 schedule 同时出现，不能在没有融合器语义/代码证据时自行相乘成最终有效系数。FL2VA 的 back_0.7 有记录，但没有完整层级表，不拿其它日期配方补写成 1016 配方。

FL2VA 配方只记录 OpenVDN 的 turbo adapter，没有 VDN 的 linear branch/default adapter，因此是 H3 FL2VA 上的自定义多 LoRA 融合，不等同完整 VDN-H3。FL2VA 可做 T2V、单参考帧或首尾双参考；名称不是 T2VA-only。

LoRA 是以独立 scale 加到 base 权重的 delta，并非把 base 和三个 LoRA 权重按百分比归一化混合。REF2VA manifest 描述 FP32 融合、QKV 从 [q_all;k_all;v_all] 重排为逐头交错 [q,k,v]、转 BF16，再做 128×128 block FP8 E4M3 量化；敏感输出/投影层不量化。FL2VA 1016 的详细导出流程不足，不能套用 REF2VA 记录。

**产线边界：**以上是截至 2026-11-10 可审计的最新配方/产物命名；SGLang 快照是 dev build，归档 e2e 日志在 qwen3_asr 导入注册失败。若问“当前服务正在加载哪个权重且健康”，还需当前部署模型路径、进程/请求日志或运行清单。本地材料本身不能证明这一点。
