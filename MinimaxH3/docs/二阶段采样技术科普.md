# 二阶段采样、视频恢复与 SeedVR：实现和速度取舍

> 更新：2026-11-12。依据本目录 SGLang 两阶段源码、CLI/API 配置与 2026-11-10 产线记录整理。
> 本文里的耗时公式是计算量估算，不是跨硬件实测。归档里有一条 SGLang e2e 启动失败记录，因此“代码有实现”不等于“生产服务已验证运行”。

## 1. 先分清三种目标

| 目标 | 手段 | 改动发生在哪 | 会不会减少 H3 NFE |
|---|---|---|---|
| 同等画布更快出片 | DMD、SGMD 等少步蒸馏 | 训练出少步 student / LoRA | 会，取决于部署的 student sampler |
| 低成本做高清生成 | 二阶段采样 | 生成过程中切换 latent 尺度 | 不一定；把一部分调用放在低分辨率 |
| 已有成片更清楚 | SeedVR/SeedVR2、SwiftVR、像素超分 | H3 解码之后，独立恢复模型 | 不会；还会追加后处理时间 |

二采是生成过程的一部分；SeedVR 是生成完成后的恢复。两者目标相邻，但不能互相替代。

## 2. 二采做什么

常见的 Full-X0 路线：

1. H3 在目标约一半的宽、高上生成 draft，先确定主体、构图和运动。
2. 把视频 latent unpatchify 成时空张量，经学习式 3D latent upscaler 放大后再按 H3 约定 repack。
3. 按目标噪声强度重新加噪：xσ = (1−σ)x0 + σ·ε。
4. 在目标分辨率继续用 H3 去噪，解码得到成片。

latent 通道和 patch 约定需要保持一致。学习式 upscaler 建立放大后 latent 与 H3 空间网格的映射；简单双线性/三线性插值只是重采样，不会自动恢复真实高频细节。视频音频 latent 不做相同的空间放大，但采样进度需要同步。

### 两种切换位置

| 路线 | 怎么切 | 速度影响 | 画质特点与风险 |
|---|---|---|---|
| Full-X0 | 低清完整跑到 x0 → 放大 → 重加噪 → 高清 refine | 清晰的实现路径；低清段便宜，但有 upscaler 和高清段开销 | draft 结构较稳；高清段用随机性重画细节，噪声越大越容易漂移 |
| Mid-trajectory | 低清轨迹中途取当前 x0 预测/映射，放大后接后续 σ | 可以省掉低清尾段，理论上更快 | 预测误差会被放大；切换后的 sigma 必须单调并与 scheduler 对齐，调参更难 |

σ 控制保留 draft 与重画的比例：σ 高，高清段从更噪的状态重新生成，细节变化较多但语义漂移风险上升；σ 低，更接近轻度打磨，保留结构更多，但新增细节有限。它不是单纯“清晰度旋钮”。

## 3. 为什么有时更快，有时反而更慢

先估计注意力项。宽和高各减半，视觉 token 数约变为 1/4；若 dense attention 的主成本近似 token²，低清单步注意力项约为高清的 1/16。

用 8+5 的例子：

- 13 步全高清：13 × 16 = 208 个“高清注意力单位”；
- 8 步低清 + 5 步高清：8 × 1 + 5 × 16 = 88 个单位；
- 这只说明 attention 项的理想估算约少 58%；真实端到端还需加 upscaler、VAE、调度、非注意力算子、显存搬运和服务开销。

总耗时可写成 T ≈ N₁·c_low + T_up + N₂·c_high + T_decode。

因此：

- 对比“同样 13 步都在高清跑”，二采可能更快，因为大部分调用发生在低 token 尺度。
- 对比“4-step 高清直出”，8+5 会多出 9 次 H3 NFE，还要跑 upscaler，通常更慢。
- 对比“已经解码好的视频”，SeedVR/SeedVR2 还要再跑一个独立恢复网络，必然增加这条后处理链路的时间。
- 低分辨率、短视频、稀疏 attention 或强 CPU offload 会改变主要瓶颈；理论 token 比率不能直接当端到端加速比。

## 4. 二采及相邻方案的分类

| 路线 | 何时处理 | 做法 | 时间账 | 主要取舍 |
|---|---|---|---|---|
| Full-X0 latent 二采 | 生成中 | 完整低清 draft、学习式 3D latent 放大、重加噪、高清 refine | 可能省高分辨率 DiT 计算，需付 upscaler 和高清 NFE | 时序整体建模；能重新生成纹理，也可能改动语义 |
| Mid-trajectory 二采 | 生成中 | 从中间状态切换分辨率并接轨迹 | 少跑低清尾步；桥接逻辑增加复杂度 | 轨迹连续性与切点误差要重点验收 |
| 简单 latent 插值 | 生成中 | resize latent 后继续采样 | 省 learned upscaler 的模型成本 | 插值只补网格，不等于学会高频语义；容易软化 |
| 像素域 i2i | 两段采样之间 | VAE 解码 → 像素超分 → VAE 重编码 → 低 denoise refine | 增加 VAE 往返和像素超分 | 可借用现成超分器，编解码与重绘会改外观 |
| 局部裁剪精修 | 生成后或局部重采样 | 跟踪脸、手、文字等区域，单独做高清处理再合成 | 只处理小区域，但有检测、跟踪、拼接成本 | 全局 token 少；有接缝、身份漂移和跨帧抖动风险 |
| 逐帧图像超分 | 成片后 | 每帧独立放大 | 增加像素模型耗时 | 可能闪烁；模型没有跨帧约束 |
| 视频恢复模型 | 成片后 | 输入低质视频，时空窗口内恢复/超分 | 追加一段恢复模型耗时 | 时序建模通常好于逐帧方法，但模型也可能推断/改写细节 |
| attention/cache/offload | 每个 H3 去噪步内 | 换算子、少算 token 交互或复用中间特征 | 是否加速取决于 attention/显存是否是瓶颈 | 不改变采样 NFE；近似或缓存可能影响质量 |

局部裁剪、像素 i2i 与 attention/cache 是可选工程路线，不代表当前 H3 产线都已启用。比较时要固定 H3 权重、seed、画布、总 NFE 和后处理链路，单独改变一个因素。

## 5. SeedVR / SeedVR2 为什么可能更清晰但更慢

- SeedVR 是针对视频恢复的扩散框架，使用时空建模和窗口注意力处理长视频与大尺寸输入。
- SeedVR2 是后续视频恢复模型，论文提出一步扩散生成与对抗式后训练，并结合特征匹配和自适应窗口注意力。
- “一步”指恢复模型自己的扩散步数。它仍要加载并执行独立的恢复网络；网络规模、窗口数量、分辨率、时长、分块和 I/O 都会影响耗时，所以不是免费的一次 resize。
- 恢复网络利用训练先验补充输入里不清楚的纹理。观感可能更锐，但细节是模型推断出来的，局部身份、文字、纹理可能发生变化；不能承诺内容完全不变。
- 仓库里的 SwiftVR 集成被归为 SeedVR2-family，只能说明技术路线相近，不能据此断言部署的就是官方 SeedVR2 权重。

| 比较项 | 二采 | SeedVR / SeedVR2 类恢复 |
|---|---|---|
| 输入时机 | H3 采样还没结束 | H3 已解码成片 |
| 主要作用 | 在高清 latent 上继续生成 | 从低质视频估计更清楚的时空细节 |
| H3 NFE | 运行两段 H3 sampler，NFE 取决于两段步数 | 不减少已经执行的 H3 NFE |
| 时间 | 可能比相同步数全高清省；相对 4-step 直出未必快 | 追加独立模型的恢复时间 |
| 内容变化 | σ 越高，重绘越多 | 先验补细节可能改变局部内容 |
| 适用情况 | 生成时需要更高分辨率 | 已生成视频需要恢复/超分 |

两者可以串接，但应分别衡量 H3 生成时间、后处理时间、细节保真和时序稳定性。

### 入口默认值不完全一样

| 入口 | 归档默认 | 说明 |
|---|---|---|
| CLI infer.py | 非 480P 默认两阶段 8+5；480P 默认单阶段 9 步 | 可用命令行参数显式覆盖；总步数也可显式指定 |
| Agnes API mapping.py | 非 480P 默认启用；split step 默认 4；480P 默认旁路 | 请求字段可覆写，环境变量提供缺省值 |

所以不能脱离具体入口说“线上统一默认是 8+5”或“统一 split=4”。8+5、4+4、其它总步数/切点都是可配组合，先看请求 payload 与入口配置。

**归档证据边界：**Agnes 权重与 SGLang 记录见 [Agnes 权重融合与 SGLang 产线记录](Agnes权重融合与SGLang产线记录.md)。该记录里的 e2e 启动在 qwen3_asr Transformers 配置注册导入时报错并退出；源码、参数和权重 merge manifest 可审计，但那条日志不能证明对应服务成功生成视频。文件里记录的 8N+1 scheduler 调度也不等同于二采的 8+5 调度。

## 7. 调参和验收顺序

1. 固定 base 权重、LoRA 组合、seed、画布、视频长度和 attention 后端，先跑单阶段基线。
2. 选择 Full-X0 或 Mid-trajectory，并确认总 NFE、切点、scheduler 的 sigma 单调。
3. 从低一些的重加噪强度开始；逐级提高 σ，观察细节增益与主体漂移的拐点。
4. 单独记录 first-stage、upscaler、second-stage、VAE 和恢复模型耗时，不只看总耗时。
5. 用同一批 prompt 对比主体一致性、运动/闪烁、脸手细节、文字准确率和音画对齐。
6. 如果问题只在成片小区域，单独试局部精修或恢复模型；如果全局结构/运动错了，后处理不应被当成二采替代品。
