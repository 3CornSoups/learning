# 单条视频下载验证

本文记录此前保存 HTML 下载单条视频的验证阶段。后续已新增 `crawl_feed.py` 并完成不传视频链接、从推荐页自动发现及下载的本地验收；当前用法和范围以同目录 `readme.md` 为准。

2026-11-10 实测作品 `7704972098715913472` 下载成功：196,932,318 字节，MD5 `2bd7d9e7a7581fb16b10590d04034468` 与页面元数据一致。文件含音视频轨道，时长约 656.5 秒；开头、中间、结尾抽帧解码均通过，实际分辨率 1920×1080。下载进程已退出。

原有 `download_douyin.py` 和 `download_by_urls.py` 暂未修改，也尚未完成运行验证。

新增 `download_from_page.py`，读取登录浏览器保存的原始 HTML 响应，从 `RENDER_DATA` 中寻找指定作品，使用其主播放地址下载完整 MP4。此步骤不需要在聊天中提供 Cookie。

```powershell
python .\download_from_page.py --page .\test_page.html --aweme-id 7704972098715913472
python .\verify_media.py .\verified_downloads\7704972098715913472.mp4
```

运行下载脚本需要 `httpx`。验证脚本另需 OpenCV（`opencv-python`）；当前本机环境已经具备两者，本次未向现有环境安装依赖。

下载使用八个分段连接，按服务器 `Content-Range` 校验范围后顺序合并。中断后的 `.part` 前缀和对应分段可在重新运行时复用。最终以页面给出的文件大小、MD5（存在时）核验，通过后才改名为 `.mp4`。已存在的完成文件不会被覆盖。失败时返回非零退出码，并保留未完成数据。

验证脚本检查 MP4 容器完整性、音视频轨道及轨道时长，并尝试解码开头、中间和结尾三处视频帧；它不进行音频解码，也不代表逐帧验证全片。

输出中的同名 `.json` 为大小和散列报告，`.validation.json` 为轨道和抽帧验证报告。报告不保存签名媒体 URL 或 Cookie。

## 当前范围

此工具验证保存页面到真实视频文件的链路，需要人工保存页面。它尚不具备自动打开浏览器、按主页翻页、批量获取作品、图集采集等功能，不能替代后续的浏览器采集实现。

页面内的签名播放地址可能过期。遇到 HTTP 错误时应从已登录浏览器获取新页面响应，不应将错误页面当作视频保存。

HAR、HTML、Cookie、浏览器配置目录和下载文件均已加入本目录 `.gitignore`，请保留在本地。
