# B站服务器随机下载使用说明

代码目录：`./bilibili`

所有命令都在Linux服务器终端执行。视频保存在服务器，本机无需保存视频文件。

## 先看当前能做什么

- **视频下载已验证成功**：服务器可以解析BV视频信息、分段下载并合并音视频。
- **随机抽样已验证成功**：可以从已有候选链接中随机抽取、跳过已下载内容、过滤过长视频。
- **任意关键词实时搜索尚未在本服务器匿名跑通**：搜索接口返回需要验证。没有Cookie和候选TXT时，不能保证只输入关键词就直接下载。
- 默认数量已调为 **20条**。实际数量还受候选数、时长限制、已下载记录、账号权限和网络状态影响。
- 新入口不再默认使用某个固定关键词或旧的候选清单。

## 一、只有关键词，没有TXT，

不给Cookie  尝试实时搜索的命令是：

```bash
cd ./bilibili
./run_search_random.sh "自然风景" --count 20
```

把“自然风景”替换成自己的搜索关键词。这里的提示词会作为B站搜索词，建议使用简短的主题词。

**当前服务器匿名搜索要求验证，因此这条命令可能提示被拦截，尚不能当成已经跑通的实时搜索方案。** 程序会明确报错，不会偷偷使用旧关键词或旧清单继续下载。

不提供Cookie时，可以先通过正常浏览器搜索，取得候选链接后再由服务器下载。也可以把新关键词告诉助手，由助手读取公开搜索结果并把候选链接放到服务器，不需要自己手动整理TXT。

有cookie：cd ./bilibili
./run_search_random.sh "雪" --cookie-header-file ./bilibili.txt --count 10 --pool-size 100 --max-duration 600

## 二、已有搜索结果TXT：无Cookie随机下载

准备一个UTF-8文本文件，每行一个完整BV视频链接或BV号。把它上传到代码目录，例如命名为 `候选链接.txt`。

```bash
cd ./bilibili
./run_search_random.sh "自然风景" --candidates-file "候选链接.txt" --count 20
```

这里的关键词用于标记本次任务和输出目录；候选链接应来自对应关键词的搜索结果。

默认从最多100条候选中随机抽取，跳过已经下载的条目，默认跳过超过300秒（5分钟）的视频。候选不足时，可能少于目标20条。

想处理更多候选或下载更多视频：

```bash
./run_search_random.sh "自然风景" --candidates-file "候选链接.txt" --count 30 --pool-size 200
```

候选池上限为200条。多次运行会累计增加服务器上的视频；程序使用下载历史避免重复。

### 候选链接从哪里来

1. 在正常浏览器中打开B站，搜索自己的关键词。
2. 取得结果页视频链接，保存为TXT，每行一个。
3. 通过已连接服务器的VS Code将TXT上传到代码目录。
4. 执行上面的命令。

已有的网页导出工具为同目录的 `导出本页视频链接.html`，使用方法是将其中的导出链接保存到浏览器收藏夹，再在B站结果页点击。它只导出本页已加载的视频链接，不读取Cookie，也不会自动翻页。搜索结果可能含相关但不符合预期的视频，下载前可自行检查TXT。

## 三、更换指定视频，不随机

在服务器VS Code中打开：

```text
./bilibili/bilibili_urls.txt
```

每行填写一个新视频的完整BV链接或BV号，保存后运行：

```bash
cd ./bilibili
./run_batch.sh --limit 20
```

不写 `--limit` 时也默认处理前20条。这里按清单顺序处理，不随机。已下载或超过时长限制的条目可能被跳过，所以前20条不一定产生20个新文件。

换另一份清单：

```bash
./run_batch.sh -i "其他视频.txt" --limit 10
```

当前服务器入口按P1处理；优先填写完整的BV视频地址，不要使用Windows路径写法。

## 四、常用参数

| 需求 | 随机模式 | 指定链接模式 |
| --- | --- | --- |
| 数量上限 | `--count 20` | `--limit 20` |
| 最长10分钟 | `--max-duration 600` | `--max-duration 600` |
| 最高720p | `--height 720` | `--height 720` |
| 输出到新目录 | `-o ./bilibili/new_videos` | 同左 |
| 只检查信息，不下载视频 | `--resolve-only` | `--simulate` |

随机模式的 `--resolve-only` 会保存少量解析信息，但不下载视频；`--search-only` 只获取候选链接，仍受实时搜索验证限制。`--seed 42` 可以固定候选打乱顺序，但搜索结果和下载历史变化时，最终结果也会变化。

## 五、文件保存在哪里

- 随机模式：`bilibili_videos/search_关键词/`
- 指定链接：`bilibili_videos/by_urls/`
- 下载历史：`bilibili_videos/downloaded.txt`
- 随机任务报告：`work/search_resolved/run_report.json`
- 指定链接报告：`bilibili_videos/urls_run_report.json`

按 `Ctrl+C` 停止。保留未完成的 `.part` 文件，再运行相同命令可续传。删除视频但保留下载历史时，程序仍可能跳过该视频；需要重新下载可指定新的输出目录。

## 六、为什么之前的命令找不到

服务器是Linux，请使用：

```bash
./.venv/bin/python
```

`run_batch.sh` 和 `run_search_random.sh` 已经自动使用这个Python环境，不必另行激活 `~/projects/list`。不要在服务器执行Windows的 `.venv\Scripts\python.exe`。

查看参数：

```bash
./run_search_random.sh --help
./run_batch.sh --help
```

## 七、关于登录状态

本次没有使用用户Cookie。如果以后愿意提供，脚本支持通过 `--cookies` 读取Netscape格式文件，或通过 `--cookie-header-file` 读取F12复制的单行Cookie请求头文件。

Cookie只保存在自己的服务器，文件权限可设为600，不要发到聊天或提交到仓库。即使有Cookie，也不能保证消除站点的验证要求。
