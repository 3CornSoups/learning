## 1. 总览：四项工作分别改了 RAG 的哪一层

RAG（Retrieval-Augmented Generation，检索增强生成）通常先从外部语料检索证据，再把证据交给语言模型生成答案。语料变大、内容更新或用户问题转向新领域后，系统会面对几类不同困难：事实之间有时间变化或冲突，索引不再适合新分布，多跳问题需要把不同文档连接起来，或者新增数据导致结构重建成本太高。

这四项工作的焦点可以概括如下：

| 工作 | 主要变化 / 痛点 | 主要操作对象 | 核心方法 | 主要评估目标 |
| --- | --- | --- | --- | --- |
| ProStruct-RAG | 旧事实、新状态、矛盾说法和错误信息混杂 | 带时间的命题及命题间关系 | 抽取命题；建立更新、矛盾、支持边；检索关系子图 | 时间敏感问答准确率、关系标签消融 |
| AURORA | 新主题或新术语造成检索分布漂移 | 稠密、稀疏和生成式检索索引 | 少样本元学习适应、轻量更新、不确定性路由 | Recall@10、适应时间、延迟与部分记忆指标 |
| GFM-RAG | 多跳证据分散，普通检索或静态图推理受噪声和缺边影响 | 文档图及图上实体 | 查询条件 GNN、图基础模型预训练、实体到文档排序 | 多跳 QA 检索召回与最终问答效果、跨图泛化 |
| HyperRAG-IHM | 新文档到达后全量重建昂贵，直接追加会累积重复关系 | 超图中的低阶超边 | LSH 候选定位、多信号比较、合并 / 替换 / 保留 | 增量构建成本、结构规模、答案质量 |

它们不能被简单看作四个互相替代的 RAG 系统。ProStruct 关心“事实之间的关系怎么表示”；AURORA 关心“新分布下检索索引如何恢复”；GFM-RAG 关心“如何利用图结构来找多跳证据”；IHM 关心“已有超图怎样吸收新增关系”。新增文档、事实修订、查询漂移和跨域迁移是不同实验条件，论文中对其中一个问题的结果不能自动外推到另一个问题。

### 用一个例子区分它们

假设一个知识库里有某实验室的负责人信息：2024 年材料称负责人为林某，2026 年公告称负责人改为陈某，另一份材料却声称负责人是王某；最近的新文档还引入一个旧检索器不熟悉的缩写。

- **ProStruct-RAG**：把陈述拆成命题，表达“2026 陈某”更新了“2024 林某”，并将王某的同一时段说法标成矛盾候选。问题是如何让模型看懂证据关系与时间。
- **AURORA**：用少量新样本适应检索度量或术语扩展，并根据不确定性选择稠密、稀疏、生成式或回退分支。问题是新主题到来时怎样找得到相关材料。
- **GFM-RAG**：如果要回答“现任负责人在哪所大学毕业”，可从问题实体沿知识图中的关系传播，寻找多文档证据。问题是如何学习图上的查询相关检索。
- **HyperRAG-IHM**：新材料到来后抽取新的超边，寻找局部相似的旧超边，决定合并、替换或并列保留。问题是怎样以较低成本更新关系结构。

这只是概念示例，不是论文实验，也不意味着四种技术拼接后一定有效。

## 2. ProStruct-RAG：显式表示命题间的更新、矛盾和支持关系

### 论文信息与问题

**Beyond Retrieval: Structuring Evolving and Inconsistent External Knowledge with Proposition Relations for RAG** 由 Noriki Nishida、Fei Cheng 和 Yuji Matsumoto 撰写，发表于 EMNLP 2026，论文编号 `2026.emnlp-main.294`，页码 6749–6771。

论文关注的是随时间变化、彼此冲突或混有错误信息的外部知识库。普通 RAG 可以找到相似文本，却不一定知道新旧说法之间是什么关系。只把命题按日期排序也不够：后来的说法可能是修订，也可能是矛盾、补充或无关陈述。作者提出 Proposition-Structured RAG（ProStruct-RAG），把处理一部分证据整合工作的时机从回答阶段前移到知识整理阶段。

### 知识结构：命题节点和有向关系边

文档被拆为简洁、可独立理解的命题节点，每个命题使用来源文档的发布日期作为时间戳。然后构建有向关系图，作者定义三种主要关系和一个筛除标签：

| 标签 | 含义 | 直观例子 |
| --- | --- | --- |
| `updates` | 新命题更新先前有效的信息 | “负责人于 2026 年改为陈某”更新“2024 年负责人是林某” |
| `contradicts` | 两个命题对同一状态给出互不相容的说法 | 同一时间的两份材料分别称负责人是陈某和王某 |
| `supports` | 一个命题提供支持另一命题的证据、理由或前提 | 一项试验结果支持一条结论 |
| `NOREL` | 没有清楚逻辑关系，包括近义重复 | 只是在说相关主题、但不构成支持或冲突 |

边有方向：主体通常是时间更新的一方，客体是同一时间或更早的命题。作者也说明使用来源发布日期较容易获得，但它不总等于事实实际生效时间；有条件时使用事实生效时间或有效区间会更直接。

### 系统怎样运行

1. **命题抽取**：LLM 将每篇文档分解为自包含事实，替换指代不明的表达，并继承文档发布日期。
2. **关系候选召回**：每条命题先用稠密检索找最多 20 条同日或更早的相似命题，控制候选对数量。
3. **关系分类和精炼**：较轻量的模型批量将候选对分为 `updates`、`contradicts`、`supports` 或 `NOREL`；再由更强模型复查非 `NOREL` 关系，删除不成立关系或修订标签。
4. **问题检索**：先召回与问题相关的 top-k 锚点命题，再沿入边和出边做一跳扩展，使可能被纯语义检索漏掉的更新时间链、矛盾说法和支持证据一起进入上下文。
5. **结构化上下文和回答**：将命题、时间与邻接关系转成文字，给 QA 模型，并提示它先依据证据推理再回答。

命题抽取和关系图构建在线下完成；问题相关的锚点召回、子图扩展与答案生成发生在推理时。因此这是预处理比较重的结构化 RAG 方法。作者的组件图见论文第 3 页： [ProStruct-RAG 框架图](assets/prostruct_p3.png)。

### 数据集与结果

作者使用三个时间敏感的开放书本多项选择 QA 数据集：

| 数据集 | QA 数量 | 语料规模 | 特点 |
| --- | ---: | ---: | --- |
| CLARK-News | 193 | 1,161 | 真实网络文章；保留同一问题答案至少变化三次的样本 |
| StreamingQA | 200 | 2,180 | 从多年时间跨度的新闻语料随机抽样 |
| Asteria | 180 | 396 | 本文构造的虚构世界，设计了更新、冲突与误信息以减轻预训练污染 |

比较基线包括无上下文、固定长度分块 RAG、只检索命题的 Prop RAG，以及带时间戳并按时间排序的 Prop RAG + Time。所有命题方法共用同一命题抽取结果，帮助区分时间信息和命题关系带来的效果。

在 GPT-4o、Asteria、检索量 `k=400` 的设置下，Prop RAG 的准确率为 **41.1%**，加入时间戳为 **58.9%**，完整 ProStruct-RAG 为 **86.1%**。在该数据集和设置中，去掉关系精炼后为 **83.8%**，把所有关系类型合并成一个通用标签后为 **82.2%**；分别去掉更新、矛盾、支持关系后为 81.7%、83.3% 和 80.6%。这组消融说明在该实验中，只有命题切分不足以应对时间问答；时间戳有显著贡献，而关系语义和关系精炼还带来额外收益。

| GPT-4o / Asteria / `k=400` | 准确率 |
| --- | ---: |
| Prop RAG | 41.1% |
| Prop RAG + Time | 58.9% |
| ProStruct-RAG 完整方法 | 86.1% |
| 去掉关系精炼 | 83.8% |
| 不区分关系标签 | 82.2% |

论文还报告关系邻居扩展在多种设置中继续带来改善，说明初始相似度检索可能只找到了更新链的一部分。扩大到两跳时，节点数量快速增长、上下文超限，因此本论文只系统评估了一跳扩展。

### 结果边界与可讨论问题

- **数据规模和领域有限**：实验主要是新闻式时间变化，对企业知识、科学文献或医疗资料的泛化仍未验证。
- **发布日期是代理时间**：一份文件何时发表不总能说明事实何时开始成立或失效；历史真相也不能简单视为错误并删除。
- **关系质量很关键**：消融显示关系精炼有价值，但抽错关系可能把噪声直接交给模型。不同模型、不同候选召回器的误差会怎样传播，可以进一步评估。
- **预处理成本**：关系抽取依赖 LLM。适合离线整理并长期复用的语料，是否适合频繁更新的知识库还要测更新成本。
- **污染风险并未完全消失**：虚构 Asteria 有助于控制污染。StreamingQA 的无上下文准确率高于随机猜测，作者提醒该结果可能包含参数知识或选项先验，不能把它当作完全纯净的检索推理评估。
- **真实冲突与来源可信度不同**：`contradicts` 表示互不相容，不等价于自动判定谁可信。论文并未把来源权威性当作上述三个关系标签之一。

**讨论问题：**时间关系是否应该带有效区间和来源置信度？当一个新事实更新旧状态时，是否保留可回溯的历史状态？能否在关系图上加入来源可靠性和可撤销更新，而不把“更新”误当成“旧事实从未成立”？

## 3. AURORA：让检索索引适应分布漂移

### 论文信息与问题

**AURORA: Neuro-Symbolic Continual Indexing for Evolving RAG Systems** 由 Manoj Saravanan、Rohit Kumar Salla 和 Ramya Manasa Amancherla 撰写，发表于 Findings of ACL 2026，编号 `2026.findings-acl.495`，页码 10179–10195。

论文指出，RAG 把知识放在外部索引里，并不代表系统就能自然适应变化。索引通常按旧文档和旧查询分布构建；新主题、新词汇或语义变化到来后，检索召回可能下降。全量重建或重训练成本较高；可训练的生成式索引又可能在学习新信息时遗忘旧知识。AURORA 将索引维护建模成少样本持续学习，试图在不重建所有离散结构的情况下，快速更新若干可学习组件。

### 方法分支

论文在稠密、学习型稀疏和生成式索引上实例化同一套设计思路：

- **稠密检索**：冻结编码器，并保持 HNSW 图的拓扑；对神经隐式码本和残差量化组件做轻量适应。粗粒度语义近似与细粒度词汇残差由门控组合，作者希望避免稀有术语被粗略表示抹平。
- **稀疏检索（SPLADE）**：使用低秩适配器，调整术语扩展权重，尝试让新词映射到正确语义概念。作者把这一操作称为 lexical surgery。
- **生成式检索（DSI）**：DSI 根据查询直接生成文档 ID，速度快、索引存储小，但尾部查询上可能幻觉。AURORA 读取生成置信度和困惑度，由不确定性路由器决定是否回退到向量搜索。
- **少样本适应**：用 Reptile 元学习寻找容易快速更新的初始化。论文也使用经验回放讨论对旧任务遗忘的缓解。
- **上下文路由**：路由特征包括查询熵、最大 IDF、生成置信度等。方法尝试在适应能力与静态稳健回退之间取得平衡。

### 论文报告的实验数字

原文表 2 报告，新语义簇适应的时间是 AURORA **28.2 ms**、全量重训练 **5149.5 ms**、普通微调 **892.3 ms**。这是论文测量的适应环节耗时，不等于包含离线预训练、索引维护与全链路推理在内的系统总成本。论文称 AURORA 对静态基线最高恢复 **26.9% Recall@10**，这一数值是特定新主题设置下的最大报告提升，不应当理解为所有数据集平均提升。

| 原文中的实验 | 结果 | 阅读时的口径 |
| --- | ---: | --- |
| 新语义簇适应耗时 | AURORA 28.2 ms；全量重训 5149.5 ms | 指定适应步骤的时间对比 |
| 新主题 Recall@10 | 相比静态基线最高 +26.9% | 摘要中的最高提升；不是平均值 |
| NFCorpus 上 NDCG@10 | Pure Dense 0.5093；AURORA-Sparse 0.5638 | 与 Pure Sparse 0.5638 持平 |
| DSI 混合分支准确率 / 延迟 | 74.2% / 22.85 ms | Pure DSI 43.0% / 42 ms；Pure Vector 87.6% / 5.47 ms |
| Knowledge Injection 消融 Recall@10 | 静态 0.289；完整 AURORA 0.413 | 提升 0.124，即 12.4 个百分点 |

**需要仔细解读表 4。**按其列出的“准确率”和“延迟”两项，Pure Vector（87.6%，5.47 ms）在数值上同时优于 AURORA-Gen（74.2%，22.85 ms）。作者强调的是 DSI 与向量索引之间的精度、延迟、内存折中，并称 10M 文档时向量索引约 15.36 GB，生成索引约 240 MB。故不能只依据准确率和延迟两列声称 AURORA-Gen 胜过 Pure Vector；内存优势和任务范围也必须纳入比较。生成索引大小也不等同于含向量回退分支的整个混合系统大小。

### 结果边界与可讨论问题

- **真实漂移的外部效度**：词汇漂移实验部分通过合成 token 替换实现；自然语言中的语义漂移、真实新闻演变或长期产品术语变化还需要纵向测试。
- **冻结拓扑的候选召回问题**：稠密分支保持 HNSW 拓扑，候选生成仍可能受旧空间和旧结构限制。应区分“候选没找出来”和“候选重打分不准”，并分别测召回上限。
- **快速适应依赖样本和任务设计**：论文用任务化的支持样本测试快速适应。生产中的支持信号从何而来、样本是否代表真实新分布，会影响结果。
- **持续更新可能被污染**：在线调节术语映射或路由策略，面对投毒样本和偏差反馈时有新的风险。作者也把 GPU 需求、奖励代理噪声和合成漂移列为局限或伦理问题。
- **结果口径并非同一个 benchmark**：论文覆盖多个模态和若干人工构造的漂移设定；摘要中的最高召回提升不能代替总览均值或跨域保证。

**讨论问题：**AURORA 适应的是“如何在给定候选中排序”还是也能保障新文档被候选索引访问？能否用真实时间切分测试新术语召回，同时监测旧查询退化、索引更新费用和更新样本污染？

## 4. GFM-RAG：以图基础模型检索多跳证据

### 论文与项目版本

**GFM-RAG: Graph Foundation Model for Retrieval Augmented Generation** 由 Linhao Luo 等人撰写，收录于 NeurIPS 2025。老师分享的是 [GFM-RAG 项目文档](https://rmanluo.github.io/gfm-rag/latest/)，而不是论文 PDF。为便于读论文，本资料包另外保存了 [arXiv v3 论文](papers/03_GFM-RAG.pdf) 和后续 [G-reasoner 论文](papers/05_G-reasoner_related.pdf)。

官方仓库目前把 GFM-RAG 与后续 G-reasoner 放在同一项目文档中。README 显示，原版 GFM-RAG 使用 8M 参数模型，后续 G-reasoner 有 34M 参数模型。README 也记录了 GFM-RAG 的预训练数据版本变化：初始论文使用 60 个图、超过 1400 万条三元组和约 70 万文档；后续发布的模型版本加入了更多知识图谱。论文、模型 checkpoint 和当前示例的配置属于不同时间点，不要把版本数字拼成一套单一实验结果。

### 它想解决什么

多跳问题需要跨越多个事实和文档。例如“某人在哪座城市出生，该城市属于哪个国家？”扁平向量检索可能只找到人物简介或城市资料其中之一；固定图遍历可能因图有噪声、缺失边而偏离问题。GFM-RAG 使用图神经网络（GNN）根据具体查询对图上传播相关性，估计哪些实体与问题有关，再把实体相关性映射回文档排序。

### 处理流程

1. **从文档构建图索引**：抽取实体和关系，形成知识图谱；进行实体消歧，并建立实体到文档的倒排映射。
2. **初始化查询**：把问题编码为向量；识别问题提及实体，并以问题向量初始化这些实体的节点表示。
3. **查询条件消息传递**：图神经网络沿实体关系传播与当前查询相关的消息，输出实体相关性分数。作者使用多层 query-dependent GNN，让传播过程依赖问题本身，而不是只依赖一张固定图表示。
4. **实体到文档排序**：选取得分靠前的实体；根据实体出现在文档中的倒排关系与实体频率权重汇总文档分数，再挑选 top-k 文档。
5. **生成答案**：把查询和这些文档交给下游 LLM。

训练分两阶段：先在大量知识图谱上做自监督知识图谱补全训练（遮住三元组中的头或尾实体并预测），再用带支持文档的问题数据监督微调检索器。作者报告原始 GFM-RAG 检索器约 8M 参数；训练数据为 60 个知识图谱、超过 14M 三元组及约 700K 文档。论文示意图见 [原文 Figure 2](assets/gfm_p4.png)。

### 实验结果如何读

论文在 HotpotQA、MuSiQue 和 2WikiMultiHopQA 上测多跳检索，并另外测试若干医学、客服及常识 RAG 数据集。表 1 中单步 GFM-RAG 的 Recall@2 分别为 **78.3、49.1、90.8**；对应 Recall@5 为 **87.1、58.2、95.6**。同一表的 IRCoT + HippoRAG（ColBERTv2）Recall@2 为 67.0、45.3、75.8。该表衡量检索到支持文档的能力，不等于答案准确率。

| 多跳数据集 | GFM-RAG Recall@2 | GFM-RAG Recall@5 | IRCoT + HippoRAG (ColBERTv2) Recall@2 |
| --- | ---: | ---: | ---: |
| HotpotQA | 78.3 | 87.1 | 67.0 |
| MuSiQue | 49.1 | 58.2 | 45.3 |
| 2Wiki | 90.8 | 95.6 | 75.8 |

作者的项目说明称预训练检索器可以直接用于未见数据集，也支持针对领域数据微调。它的泛化单位是经过图索引构造后的图和查询分布；新语料仍需要适配文档格式、构图、实体消歧等输入处理。README 支持从原始 `documents.json` 自动建图，也支持使用 `nodes.csv`、`relations.csv`、`edges.csv` 格式的已有图。

### 结果边界与可讨论问题

- **输入图质量依然重要**：模型希望缓解不完整或有噪声图的问题，但构图和实体消歧错误仍可能改变传播路径。
- **迁移不等于持续更新**：在未见图上可用不意味着经过多轮新增或修订后仍能稳定。迁移能力与连续学习应分别评估。
- **预训练数据规模与复现条件**：8 张 A100 上训练的论文设置与实际小规模复现门槛差距较大。作者最新 README 要求 Python 3.12 和 CUDA 12+；运行时还可能下载预训练权重。
- **版本关系清晰后再选基线**：原论文 GFM-RAG 和后续 G-reasoner 不能混称同一模型。若要复现，应记录代码提交、权重、配置与实验论文版本。
- **解释路径的含义**：GNN 的传播路径可辅助理解检索相关性，但不应直接等同于形式化证明或事实可信度解释。

**讨论问题：**能否把时间命题图或超图映射到统一图接口？若可以，节点 / 边类型如何保持语义？预训练迁移之后，新增实体、边和文档是否要在线更新索引或继续微调检索器？

## 5. HyperRAG-IHM：增量维护超图关系结构

### 论文信息与问题

**HyperRAG-IHM: Incremental Hyperedge Maintenance for Hypergraph RAG under Corpus Expansion** 由 Haoyu Chen 等人撰写，发表于 EMNLP 2026，论文编号 `2026.emnlp-main.898`，页码 20682–20693。

超图的一条超边可以连接多个人 / 实体，表示多实体共同构成的关系或主题。既有结构化 RAG 系统通常从固定语料建图；新文档到来后，全量重建需要重新扫描历史语料，直接追加则可能积累重复或相似关系。IHM 的问题定义是：只处理新文档及新抽取关系，把它们与历史结构协调起来，并尽量保持问答质量。

### 它维护的是什么结构

作者沿用 HyperRAG 表示。超边包含实体集合、文字描述、关键词、来源标识和边权。论文区分低阶与高阶超边：

- **低阶超边**表示较直接的实体关系证据，IHM 对它实施基于 LSH 的候选检索和三动作维护。
- **高阶超边**表示较宽泛的主题关联；在该方法中它们继续使用原有的实体键聚合规则。

这一范围很重要：论文不是对所有超边统一使用新的维护决策，也不是每次新文档到来都重新定义整个知识表示。

### 新关系如何被维护

1. **增量抽取**：只对新到的一批文档抽取关系证据，不重新抽取历史文档。
2. **生成候选**：用规范化实体集合键、LSH 相邻桶和实体重叠等线索找到有限数量的旧低阶超边；LSH 是辅助索引，主超图仍是检索结构的权威状态。
3. **多维比较**：评估实体、关键词、来源重叠，文本语义相似度，来源支持度和描述特异性等信号。
4. **选择动作**：新超边与候选关系可以合并、替换旧关系或与旧关系并列保留。兼容的重复证据可并入现有记录；新证据更完整或更有支持时，可能替换旧记录；不够相似或不确定时默认两者并存。
5. **分阶段提交**：先生成更新和删除列表，写回主超图成功后才提交辅助 LSH 状态，降低两套状态不一致的风险。

决策树使用论文附录里经验设定的阈值。新边的比较决策成本描述为 `O(|ΔE_low| · M)`，其中 `ΔE_low` 是新低阶超边，`M` 是候选数量上限。这个量级不包含新文档关系抽取本身的成本。

### 实验结果

评测使用 Pathology、Neurology、MixCorp 和 MuSiQue。Pathology（5,297 篇文档、5,289 个索引块）是主要分析集；测试同时包含单跳和多跳问题。效率实验在 Pathology 上模拟 **5% 语料更新**，将增量维护与全量重建对照：

| Pathology 单次 5% 更新方法 | LLM tokens（百万） | 时间（秒） |
| --- | ---: | ---: |
| HyperRAG-IHM | 1.63 | 1,221.06 |
| HyperRAG 全量重建 | 32.95 | 22,947.62 |
| GraphRAG | 47.46 | 10,334.08 |
| LightRAG | 32.51 | 1,554.29 |

因此在该次 5% 更新测量中，IHM 对 HyperRAG 全量重建使用约 1/20 的 token、约 1/19 的时间。该数字是构建成本，不是在线查询延迟，也不能直接推广到所有语料大小、更新比例或部署硬件。

质量主要由 LLM 裁判评估。Pathology 主评估中，IHM 的 5D 绝对平均分在单跳和多跳设置分别为 57.80、66.77；与 HyperRAG 的 8D 两两比较中，IHM 在**明确偏好**的比较项中占 58.25%。跨数据集时结果有变化：Neurology 5D 为 IHM 54.32、HyperRAG 53.72；MixCorp 为 53.39、54.65，后者全量重建稍高；MuSiQue 为 62.71、61.26。不能把 58.25% 解读成准确率，它是成对比较中裁判偏好率。

在 Pathology 和 Neurology 上，论文报告 IHM 的低阶关系条目分别比全量 HyperRAG 结构少 20.8% 和 17.3%。这支持其合并重复关系的效果，但结构更小本身并不证明事实更正确。

### 结果边界与可讨论问题

- **模拟增量不等于真实时间流**：数据是静态集合上模拟分批更新；论文明确指出真实文档修订、时间冲突和时效性敏感问题还没有测。
- **阈值为经验设定**：还没有通过数据学习或系统校准阈值。新领域改变描述风格或实体密度后，策略是否稳定需要单独验证。
- **自动裁判的影响**：主实验使用 Doubao-1.5-Lite 评判，虽有其他裁判敏感性分析，5D 排序会随裁判变化；目前没有人工标注结论。
- **跨域结果不是全都胜出**：MixCorp 上全量重建 5D 分数更高。因此更准确的结论是增量维护大幅节省特定更新成本，多个设置下质量具有竞争力，而不是每个数据集都胜过重建。
- **结构动作的语义边界**：相同实体集可能代表不同关系；语义相似也不一定意味着可以合并。保留被“替换”的旧证据以便历史时间查询，可能需要额外的版本或有效期机制。
- **来源与冲突**：IHM 使用来源支持信号决定维护动作，但它不等同于事实核验器；论文也没有声称通过它解决所有来源可信度问题。

**讨论问题：**若历史证据被替换，如何确保之后还能回答“当时已知什么”？能否把维护动作设计为保留带来源、时间和版本的审计记录，而不是仅更新活动超边？

## 6. 横向比较与研究问题

### 比较时应统一的维度

| 比较维度 | 要问的问题 | 对应工作 |
| --- | --- | --- |
| 知识变化的类型 | 新增文档、事实状态更新、来源冲突、词汇漂移还是领域迁移？ | 四者实验条件不同，需明确任务 |
| 处理的结构 | 文档块、命题图、实体知识图、向量 / 倒排索引、超图？ | ProStruct、GFM、IHM 的结构对象不同 |
| 更新范围 | 是更新编码 / 排序模型、更新新节点，还是改写旧关系？ | AURORA 与 IHM 的“更新”指代不同层次 |
| 证据可追溯性 | 能否回答某一时刻依据什么来源做了判断？ | ProStruct 有文档时间戳；IHM 可保留来源集合；仍需统一协议 |
| 质量指标 | 测支持文档召回、开放书本正确率、LLM 裁判得分还是偏好率？ | 不同数值不能直接排榜 |
| 更新成本 | 报告的是离线训练、每批维护、索引构建，还是单次查询？ | AURORA 与 IHM 的报告口径不同 |
| 旧知识保持 | 学到新主题或替换记录后，旧问答是否退化？ | AURORA 讨论遗忘；其他方法需要单独测长期保持 |

### 可能的研究切口

以下是供和老师讨论的假设方向，尚未验证新颖性或可行性：

1. **把语义维护和时间有效性结合起来**：对新旧证据不只做相似度聚合，而明确区分“重复支持、状态更新、同一时点冲突、不同时间都成立”。这是将 ProStruct 的命题关系与 IHM 的增量结构维护放在同一问题中考虑。
2. **研究增量图检索器的长期表现**：固定预训练 GFM-RAG，按时间逐批增添、修订图结构，记录支持文档召回、新旧问题性能和更新成本，测量迁移能力是否会被持续更新破坏。
3. **统一评估协议**：设定带时间的新增 / 修订流，比较全量重建、直接追加、实体键聚合、显式关系维护与轻量适应；同时报告 QA、证据召回、历史查询、结构增长和更新预算。
4. **把“撤销”作为一等操作**：新增证据可能是错的，若曾传播到命题图或超边图，系统如何标记撤回、追溯受影响回答和修复索引？这比只测新增事实更接近有审计要求的真实知识库。

研究上不宜直接宣称把四篇方法组合就有创新。先选一个明确变化类型，找到各自方法没有覆盖的指标和假设，再决定是否整合模块。

## 7. 建议阅读顺序与讨论提纲

### 阅读顺序

1. **先读本节总览和例子**：确认四项工作对应不同问题。
2. **ProStruct-RAG**：看原文 Figure 1、§3 和表 3–4，理解命题关系与时间信息各自的贡献。
3. **HyperRAG-IHM**：看 §3–5、表 1–6 和局限，区分低阶 / 高阶超边与增量成本。
4. **GFM-RAG**：看 Figure 2、§3、Recall 表及作者 README，分清原论文与 G-reasoner 版本。
5. **AURORA**：看方法、表 2、表 4–6 和局限，核对时间、Recall、准确率、延迟和内存口径。

### 和老师讨论时可以先问

1. 我们最关注的是新文档接入、旧事实修订、查询分布漂移，还是跨领域迁移？
2. 研究对象应以命题关系图、实体图、超图还是普通向量索引为主？时间和来源如何编码？
3. 若做增量评估，能否同时和全量重建、直接追加、键聚合比较，并统一硬件 / 模型预算？
4. 除答案质量，是否测支持证据召回、历史时点正确性、旧任务遗忘、结构增长和每批更新费用？
5. 能否以 Asteria 或一个小型时间语料先做可控基线，再扩展到真实领域数据？

### 90 秒概述

> 我把四项工作放在动态知识 RAG 的不同环节理解：ProStruct 把命题之间的更新时间、矛盾和支持关系显式组织起来；AURORA 让检索索引适应新主题和术语漂移；GFM-RAG 用查询条件图神经网络从知识图检索多跳证据；HyperRAG-IHM 让新增文档只触发局部超边维护。它们的任务和指标不同。我想进一步确认我们更关心哪种知识变化，以及能否把新知识吸收、旧知识保留、时点冲突和更新成本放进同一评估流程。
